# Manan Bhullar Real Estate Website

Static multi-page site for Manan Bhullar, a REALTOR® with Coldwell Banker Universe
Realty in Surrey, BC. Replacing his old GoDaddy Website Builder site
(mananbhullar.com). Covers residential + commercial/industrial real estate across
Surrey and the Lower Mainland.

## Tech stack & build

- Plain HTML/CSS/JS, no framework, no npm build step.
- `build.py` (Python) is the site generator — it defines the page shell, reusable
  section helpers (subhero, point_list_section, faq_section, simple_cards,
  info_cards, market_context_section, commercial_cta_form, google_follow_card,
  etc.) and a big `AREAS` data list, then calls `write_page()` for every route.
  **Run `python3 build.py` after any change** — it regenerates every HTML file
  from scratch (each page is fully overwritten, not patched).
- `index.html` is **hand-maintained**, not generated by build.py. If you change
  the shared nav (`assets/_nav.html`) or footer (`assets/_footer.html`), you must
  manually sync the same change into `index.html`'s own copies of those blocks —
  it does NOT auto-include them. This has caused real bugs before (see Gotchas).
- `assets/style.css` — all site CSS, one file.
- `assets/site.js` — mobile nav toggle, FAQ accordion, mortgage calculator,
  Realtor.ca deep-link search (`data-realtor-search` attribute).
- 138 pages currently generated. Sitemap.xml and robots.txt are auto-generated
  at the end of build.py by walking the output directory — do not hand-edit them.

To preview: unzip, drag the folder into app.netlify.com/drop (or now that you're
on Claude Code, just run a local static server / open in a browser — root-relative
asset paths like `/assets/style.css` need an actual server, not `file://`).

## Known bug pattern — watch for this specifically

**CSS Grid track blowout from `<img>` HTML width/height attributes.** Any
`display:grid` container using `fr` units (e.g. `grid-template-columns:1fr 1fr`)
will size a track based on its content's intrinsic minimum — including an
`<img>` child's `width=`/`height=` HTML attributes — unless the grid item has
`min-width:0`. This caused two real, shipped bugs: the homepage bio photo
ballooned to ~65% of viewport width, and a commercial-page market-context photo
did the same. **Fixed with a blanket rule at the bottom of style.css:**
```css
[class*="grid"] > *, .cat-cards > *, .mega-inner > *, .calc-row-split > *, .form-row > * {
  min-width: 0;
}
```
If you add a new grid class that doesn't match `*grid*` and contains an `<img>`
with width/height attributes, add it to that selector list or you'll reintroduce
this bug. Verify any new photo-containing grid by actually rendering it (see
Testing below) — don't just eyeball the HTML.

## Testing approach used throughout this project

No live hosting is connected yet (deferred — see Pending Work). Verification
was done by:
1. `python3 build.py` and check exit code / no traceback.
2. A Python script inlining `assets/style.css` directly into the HTML (since
   root-relative `/assets/style.css` won't resolve via `file://`), stripping
   external font `<link>` tags (no network in some sandboxes), then rendering
   with Playwright (`chromium.launch()`) and screenshotting.
3. Link-checking script: regex all `href="/..."` across every generated page,
   verify each resolves to a real file on disk.
4. Checking `document.documentElement.scrollWidth` vs `clientWidth` at both
   1280px and 375px viewports to catch horizontal overflow bugs.
This caught real bugs (grid blowout, broken `\u2192` escape literal instead of
→ in the footer, duplicate `<title>` tags on the two Sullivan Heights pages,
missing meta descriptions on legal pages, non-functional "Learn More" links on
info cards) that shipping without visual verification would have missed. Keep
doing this — don't ship based on reading the HTML source alone.
